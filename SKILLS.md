# Skills

The skill tree is **not** part of this repository. This file exists so a fresh
machine can be brought back to the same skill inventory without the repository
ever redistributing unlicensed content.

## Why

The original private snapshot carried 846 skill directories. A license census
found 8 with an explicit `LICENSE` file and the rest — Azure/Microsoft sample
skills, community skill packs, and assorted public collections — with **no
license file at all**. Absent an explicit grant, those are all-rights-reserved
by default. Copying them into a private personal backup is defensible personal
use; republishing them is a different act entirely, so the tree was left out of
the public repository.

The per-component analysis, including which directories were cleared and which
were not, is in [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

## How the skills are installed

OpenCode discovers skills by directory convention — a directory under
`~/.agents/skills/` containing a `SKILL.md` with YAML frontmatter (`id`, `name`,
`description`). There is no central registry to re-sync from, so restoring means
re-obtaining each skill from wherever it came from.

```sh
mkdir -p ~/.agents/skills
git clone <upstream> ~/.agents/skills/<skill-id>   # or copy SKILL.md in by hand
```

The `opencode-froggy` plugin contributes 4 further skills (`tdd`,
`extreme-programming`, `backlog-management`,
`ask-questions-if-underspecified`) automatically once the plugin is installed —
see `INSTALL.md` step 5. A complete install advertises those 4 on top of the
list below.
